## 方法学修正（本次实际修掉的七个错误，答辩可能被问到）

### ① 超几何检验的尾部方向错误

**原写法**：只算右尾 `hypergeom.sf(k-1, ...)`，然后用 `fold > 1` 判"偏向"、`fold < 1` 判"回避"。

**问题**：右尾 p ≈ 1 只意味着"**没有证据表明富集**"，不能推出"回避"。S2/S3/S4 的 `p = 1.0` 配 `fold = 0.43~0.53` 看着像"显著回避"，其实是"未拒绝原假设"。

**修正**：改为双单尾——`p_up = sf(k-1)` 支持富集结论，`p_down = cdf(k)` 支持耗竭结论，各自配对判定。
**修正后的结果**：S2 左尾 p = **2.4×10⁻¹⁷**（A），这才真正确立了"显著耗竭"。同时 S3、S4 在高共识版本中回落为"不显著"，如实保留。

### ② 派生列混入特征矩阵

`celltype_age_profile.tsv` 除 16 个 `S*` 列外还有 `TAI_se`、`n_cells`、`low_confidence` 三个派生列。若用 `prof.drop(columns=["TAI"])` 构造特征矩阵，这三列会被误当作特征，造成信息泄漏。
**修正**：统一用 `[c for c in prof.columns if c.startswith("S")]` 显式取列。

### ③ `numpy.argmax` 遇 NaN 返回 NaN 位置（数字张冠李戴）

**原写法**：`k = int(se.values.argmax())` 取下标 + `se.max()` 取数值，拼成"标准误最大（0.1323，← 某类型, n=1）"。

**问题**：`se.max()`（pandas）跳过 NaN，得到真实最大值 0.1323；而 `se.values.argmax()`（numpy）遇到 NaN 会返回 **NaN 所在下标**，指向一个 SE 根本算不出来的类型（n=1）。**数值和标签对不上号**，且这个错误不会让脚本报错，只会静默污染报告正文。

**修正**：改用 `se.dropna().idxmax()`，并额外打印 SE 无法计算的类型清单。修正后 0.1323 正确归属 `enterocyte of epithelium of small intestine`（n=5）。
**顺带**：`07_做网页.py` 原用 `fillna(0)` 把 NaN 变成 0，会被读成"该类型 TAI 极其精确"，已改为 `null`。

### ④ PCA 零假设的置换对象错了（基线 = 真实值，还不自知）

**原写法**：`Xp = X[perm]` 置换**细胞类型**这一行，构造"年龄构成与细胞类型无关"的零假设。

**问题**：PCA 分解的是 **16 个特征之间的协方差结构**，行置换不改变任何一行的 16 维取值，
所以基线算出来 = 真实值 = 61.9%，**z = 0**。零假设彻底失效，**却不会报任何错**。

**修正**：改为**逐列打乱**（每层内部重排，保留边际分布、破坏层间共变），
并加一道基线自检——独立正态基线 27.61% vs 逐列打乱基线 27.05%，差 0.56 个百分点，确认无残留结构。
**再加第三条同秩基线**：16 层占比是**成分数据**（行和恒为 1），协方差**秩亏到 15**
（第 16 个 EVR = 2.6×10⁻³¹），补一条 **Dirichlet 成分基线 29.03% ± 0.68%**。

**修正后的结论**：真实 61.9% vs 三条基线 27.05% / 27.61% / 29.03%，**z = 47.0 / 48.3**；
有效维度 6.12 vs 14.74（Dirichlet 13.77）；14 对 |r|>0.5 的高相关层；
逐 PC 看 PC1–PC4 的 z 为正（+37.9 / +47.1 / +14.5 / +18.5），**PC5 之后 z 转负**（−8.9 / −8.4）。
→ 「前 3 累计 > 70%」这个验收指标**设得过高**，即使各层完全独立前 3 维也只解释 27.0%。

### ⑤ Spearman 相关算成了同义反复（"完全一致"是假的）

**原写法**：`spearmanr(profile["TAI"], profile_hi["TAI"])`。

**问题**：`spearmanr()` 对 pandas Series **按位置**取值；而 `compute_age_profile()` 的返回值
**已按 TAI 升序排过**，两列各自升序后按位置配对，**位置秩相关恒等于 +1**。
所以"ρ = 1.0000、τ = 1.0000、排序完全不变"**是恒等式，不是发现**。
实测复现：两列独立随机数各自升序后做位置秩相关，**500/500 次都算出 ρ = 1.0**。

**修正**：按索引**显式 `reindex` 对齐**后再算，真实值为 **ρ = 0.9883、τ = 0.9518**。
结论改为"整体格局一致，但 141/177 个类型名次有变化，最大位移 88 位"。

### ⑥ 宏平均 F1 未显式指定类别集合

**原写法**：`f1_score(y_true, y_pred, average="macro")`。

**问题**：默认取 `y_true ∪ y_pred`，测试集里从未出现过的类别会以 0 分参与平均，把宏 F1 稀释到 **0.164**。

**修正**：显式指定 `labels=`，两个口径都报：
**测试集实际出现的 103 类口径 = 0.237**，**全部 177 类口径 = 0.138**。

### ⑦ `NumDBsContributing` 的语义被当成支持数（筛选方向反了）

**原写法**：`05_监督分析.py --min-dbs 10`，本意"至少 10 个算法支持"。

**问题**：`NumDBsContributing` 是**参与投票的算法总数（分母）**，不是支持数。
真正的共识度是 `mode_share` = 最优势层占比，支持数 = `round(mode_share × n_dbs)`。
实测 **corr(n_dbs, mode_share) = −0.128（负相关）**——参与算法多的基因往往分歧也大，
所以"高 n_dbs"筛出来的恰恰是**低共识**的基因，**方向完全反了**。

**修正**：改用 `--min-share 0.8`，保留 **905 个**特征；
在年龄表构建阶段就把 `mode_share` 一并算出并落盘，供终审脚本断言。

> **这七条的共同点**：都不触发异常，只在输出里"安静地错"。因此新增 `20-分析/07_终审核对.py`，把报告里每个关键数字做成断言与输出文件自动比对（**239 项**），任何一项不符即退出非零。这比人工复核可靠。
>
> 断言本身也不能写成"字符串出现过就算过"——本项目终审脚本用
> **精确正则定位数字位置 + 按报告的小数位舍入比对 + 作废语境标记**：
> 报告为了如实记录踩过的坑会引用旧值（如"最初报告的是 ρ = 1.0000，那是同义反复"），
> 这些出现必须被识别为**合法引用**而不是"数字不一致"。
